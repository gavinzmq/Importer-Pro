# Importer Pro 图形化配置指南

## 1. 概述

图形化配置位于导入向导的 **Step 3（模板配置）**。完整向导共 4 步，界面布局以蓝图 [ui/layout.md](../.arcmesh/ui/layout.md) 为准：

| 步骤 | 名称 | 说明 |
| :--- | :--- | :--- |
| Step 1 | 来源选择 | 选择数据文件或笔记应用（Excel/CSV/JSON/Enex/Notion/Apple Notes） |
| Step 2 | 文件管理 | 选择文件或从历史记录快速导入（显示新增条数） |
| Step 3 | 模板配置 | 本指南主题：数据处理、列映射、派生字段、匹配规则、分流、输出 |
| Step 4 | 进度执行 | 批量导入、进度展示与取消 |

以下各小节对应 Step 3 的配置内容，按向导推进顺序排列，全程无需编写代码。

## 2. Step 3：模板配置

### 2.1 数据概览

进入配置后首先显示已解析文件的数据概览（前 3 行），帮助用户了解数据结构。

```text

┌───────────────────────────────────────────────────┐
│ 姓名 │ 身份证号 │ 部门 │ 职位 │
│ 张三 │ 110101199003071234│ 技术部 │ 工程师 │
│ 李四 │ 110101198505152345│ 产品部 │ 产品经理 │
│ 王五 │ 110101199111112356│ 技术部 │ 技术总监 │
└───────────────────────────────────────────────────┘


```

### 2.2 列映射

将源列映射到目标字段。

| 配置项 | 说明 |
| :--- | :--- |
| **源列名** | Excel/CSV 的实际列名（下拉选择） |
| **目标字段名** | 模板中使用的变量名（自动填充或手动修改） |
| **字段类型** | 文本/数字/日期/身份证/邮箱/手机号 |
| **处理规则** | 额外处理（如日期格式、数字精度） |

**映射方式**：
- **自动匹配**：插件自动尝试匹配列名
- **手动映射**：用户通过下拉菜单手动选择

### 2.3 派生字段

从预设规则列表中选取。

| 规则名称 | 来源字段 | 输出字段 |
| :--- | :--- | :--- |
| 提取性别 | 身份证号 | 性别 |
| 提取生日 | 身份证号 | 生日 |
| 生成哈希 | 任意字段 | _hash |
| 智能链接 | _hash | _link |
| 拆分字段 | 标签 | 标签数组 |
| 合并字段 | 姓、名 | 全名 |

### 2.4 匹配规则

设置文件名自动匹配规则。

| 匹配方式 | 说明 | 示例 |
| :--- | :--- | :--- |
| **正则表达式** | 最灵活 | `^员工.*\.xlsx$` |
| **通配符** | 简单易用 | `员工档案_*.xlsx` |
| **精确匹配** | 完全一致 | `员工信息.xlsx` |

### 2.5 数据分流

根据条件将数据放入不同文件夹。

```text

┌─────────────────────────────────────────────────────────────┐
│ 分流条件 │
│ ┌──────────────────────────────────────────────────────┐ │
│ │ 条件: validateID 身份证号 == true │ │
│ │ 目标文件夹: 人员档案 │ │
│ │ ─────────────────────────────────────────── │ │
│ │ 条件: validateID 身份证号 == false │ │
│ │ 目标文件夹: 待核验档案 │ │
│ └──────────────────────────────────────────────────────┘ │
│ │
│ [+ 添加分流条件] │
└─────────────────────────────────────────────────────────────┘


```

### 2.6 输出设置

控制笔记生成位置和方式。

| 配置项 | 说明 |
| :--- | :--- |
| **目标文件夹** | 笔记存放路径（支持变量） |
| **笔记名称** | 文件名模板（支持变量） |
| **冲突策略** | 覆盖/追加/跳过/重命名 |
| **增量更新** | 仅当内容变更时更新 |

> **目标文件夹留空时**：回退到设置中的"默认输出目录"（`paths.outputFolder`），再未设置则写入 Vault 根。所有目录均为 Vault 内相对路径，可在设置页修改（见用户指南 §4.4）。

### 2.8 模板创建与行清洗 / 表头（2026-09-03 D92/D93；2026-09-05 D122；2026-09-06 D123/D124 更新）

**无模板也可直接新建（无需重开向导）**：模板目录为空时，Step 3 模板区块与预览区会提供 **[➕ 新建模板]**——按当前已配置选项（模板名称、匹配规则）生成模板骨架写入 `paths.templates` 并**自动选中**，可直接开始导入；名称/规则留空时按当前文件名与扩展名自动生成（如 `*.csv`），骨架预填当前数据源列名列表供后续编辑（模板骨架规范见蓝图 `template-schema.md` §8）。重名自动追加序号，不覆盖既有模板。

**表头行（D123，取代原「从第 N 行开始读取」控件）**：不再需要手动指定表头在第几行——文件按原始行解析后，按 **D124 执行顺序**处理（原「🗑 删除行」「去重」「过滤无效数据」「合并行」已废弃删除）：
1. **过滤空行（含第一行）**：所有列值 trim 后为空的行过滤（含首部空行与全空格行）；
2. **行筛选**：按用户规则过滤（占位列名 `列1..N` 匹配）；
3. **过滤重复表头行**：在行筛选**之后**执行，以剩余第一行（将成为表头的行）为基准，删除其后与其逐值相同的行；
4. **剩余的第一行自动成为表头**（其值作为列名；空值回落 `列N`；重名自动唯一化），该行移除、其下均为数据行——即使表头前的说明/占位行被筛选排除，重复表头仍基于真实将成为表头的行正确删除；前部有占位行/空行的表格也无需人工设置表头行。

**🧹 行清洗（当前能力）**：过滤空行（含第一行）与过滤重复表头两项开关，随模板保存，导入/预览一致生效（表格类顺序 = 空行 → 行筛选 → 重复表头；非表格类 = 值==列名在筛选前）。

**交互体验（D91）**：Step 3 内任何控件变更均按影响范围做**区块局部刷新**（仅预览 / 仅本区块 / 数据源级依赖链），`.ipw-body` 容器保持持久，滚动位置与输入焦点不丢，无「整页刷新感 / 跳回顶部」。行清洗/筛选配置导致表头（列名）变化时自动补充列映射。

## 3. 操作按钮

| 按钮 | 行为 |
| :--- | :--- |
| **💾 保存模板** | 仅生成模板文件（保存到设置中的模板目录 `paths.templates`），不执行导入 |
| **🚀 保存模板并导入** | 生成模板文件 + 立即执行导入 |
| **📝 切换到代码模式** | 切换到 Handlebars 代码编辑模式 |
| **🎨 切换到图形模式** | 切换回图形化配置界面 |

## 4. 配置示例

### 员工档案导入配置

列映射：
姓名 → 姓名 (文本)
身份证号 → 身份证号 (身份证)
部门 → 部门 (文本)
职位 → 职位 (文本)

派生字段：
提取性别 (来源: 身份证号)
提取生日 (来源: 身份证号)
生成哈希 (来源: 身份证号, 长度: 10)

匹配规则：
正则表达式: `^员工.*\.xlsx$`

数据分流：
validateID 身份证号 == true → 人员档案
validateID 身份证号 == false → 待核验档案

输出设置：
目标文件夹: {{_folder}}
笔记名称: {{_hash}}
冲突策略: 跳过
