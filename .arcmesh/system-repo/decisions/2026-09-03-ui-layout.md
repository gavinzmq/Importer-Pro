# 决策记录：UI 布局文档接入与蓝图同步（2026-09-03）

## 背景

新增 UI 布局设计文档 `.arcmesh/ui/layout.md`，需接入 ArcMesh 知识体系；同时发现该文档与蓝图既有多处表述不一致，一并同步。

## 决策内容

| # | 决策 | 理由 |
| :--- | :--- | :--- |
| D23 | `ui/layout.md` 注册为 **UI 设计权威文档**：加入 `config.json` contextFiles、`docs/README.md` 文档中心索引、`architecture.md` §1 引用 | 新文档此前未被 ArcMesh 索引 |
| D24 | 导入向导结构统一为 **4 步**（来源选择 → 文件管理 → 模板配置 → 进度执行），模板配置内含 7 区块；废弃"8 步向导"表述（project.md、glossary） | layout.md 为 4 步结构，与旧表述矛盾 |
| D25 | 数据源扩展至 **7 类解析器**：新增 `NotionParser`（.zip）、`AppleNotesParser`（.notes）；TSV 归入 `CSVParser`（.csv/.tsv）；依赖补 JSZip、内置 DOMParser | layout.md Step 1/2 支持笔记应用与多格式，原 5 类清单不匹配 |
| D26 | 测试栈表述对齐：集成测试 Vitest + obsidian-test-mocks，E2E Playwright + obsidian-testing-framework；取代 obsimian 表述（STANDARDS、CI_CD、CONTRIBUTING、project.md） | 技术选型已变更为 obsidian-test-mocks / obsidian-testing-framework |

## 影响

- `project.md`、`architecture.md`、`STANDARDS.md`、`glossary.md` 版本升至 1.3.0；`components/data-parser.md` 升至 1.2.0。
- 后续 UI 开发以 `ui/layout.md` 为布局依据；解析器实现以 7 类清单为准。
