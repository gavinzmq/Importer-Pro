# 钩子机制 (Hooks)

## 概述

钩子机制允许外部代码在 Importer Pro 的关键流程节点注入自定义逻辑，实现**可扩展性**和**非侵入式定制**。

## 设计目标

| 目标 | 说明 |
| :--- | :--- |
| **非侵入** | 外部代码无需修改插件核心源码 |
| **可组合** | 多个钩子可以串联执行 |
| **安全** | 钩子运行在隔离环境，不影响核心流程 |
| **可观测** | 钩子执行有日志记录和错误处理 |

> **移动端注意**：与外部 Helper 一致，移动端无 `vm` 运行时，外部注册的钩子在移动端默认不执行（见 STANDARDS.md §7）。

> **目录**：外部钩子脚本存放于插件设置指定的目录（`paths.hooks`，默认 `_hooks`），可在设置中修改，插件不硬编码路径（见 architecture.md §9.1）。

## 钩子执行流程

```
[核心流程执行]
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│  1. 触发钩子点 (Hook Point)                                │
│     ├── 检查是否有注册的钩子                               │
│     └── 无 → 跳过，继续执行                               │
│                                                             │
│  2. 执行钩子链 (Hook Chain)                                │
│     ├── 按注册顺序执行                                     │
│     ├── 每个钩子接收上下文 (context)                       │
│     └── 每个钩子返回修改后的上下文                         │
│                                                             │
│  3. 结果合并                                               │
│     ├── 所有钩子执行完毕后                                 │
│     └── 将修改后的上下文传递回核心流程                     │
└─────────────────────────────────────────────────────────────┘
    │
    ▼
[继续核心流程]
```

## 核心概念

| 概念 | 说明 |
| :--- | :--- |
| **Hook Point** | 钩子触发点，在核心流程中预定义的插入位置 |
| **Hook Chain** | 注册到同一钩子点的多个钩子按顺序执行 |
| **Hook Context** | 传递给钩子的上下文对象，包含当前数据 |
| **Hook Result** | 钩子执行后返回的结果，可修改上下文 |
