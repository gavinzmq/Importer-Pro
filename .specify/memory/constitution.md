# Project Constitution

## 架构边界

- 插件必须同时支持桌面端和移动端，所有功能必须在两端可用。
    
- 平台相关代码必须通过 `platform-adapter` 统一封装，禁止在业务逻辑中直接调用平台 API。
    
- 禁止引入任何运行时生产依赖，所有功能必须基于 Obsidian 原生 API 实现。
    

## 质量红线

- 禁止静默捕获错误（空 catch 块、被吞掉的 Promise）。
    
- 新代码最低测试覆盖率 80%，每个公开函数至少一个测试。
    
- 每个 bug 修复必须包含回归测试。
    

## 安全底线

- 禁止在代码中硬编码任何密钥、Token 或密码。
    
- 禁止使用不安全的网络协议，所有外部请求必须通过 Obsidian 的 `requestUrl`。
    

## 版本管理

- `manifest.json` 的 `version` 是版本唯一事实来源。
    
- 禁止在 SDD 文档中硬编码具体版本号。
    

## 修订流程

- 修改本文件需要在 PR 描述中说明变更理由和影响范围。
    
- 版本号遵循语义化版本：MAJOR 表示不兼容变更，MINOR 表示新增原则，PATCH 表示措辞澄清。
